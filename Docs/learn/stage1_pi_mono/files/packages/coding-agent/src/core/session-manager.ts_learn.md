## Complete behavior review

- Types and migrations (1–315): the file stores a versioned JSONL session header plus append-only entries. Entry variants cover model/thinking changes, messages, compaction, branch summaries, extension state, labels, session display names, and custom messages. IDs are short random UUID prefixes with collision checks. v1 migration assigns parent links and converts compaction indexes; v2 migration renames hookMessage to custom; migration mutates loaded entries and updates the header version. Parsing skips blank/malformed lines and accepts only a session-headed file for filesystem loading.
- Context projection (316–475): `buildSessionPath` follows the selected leaf through parent IDs and reverses to root; missing leaf falls back to the last entry. Message/custom-message/branch-summary/compaction entries map to runtime messages while plain custom, label, session-info, model, and thinking entries do not. `buildContextEntries` retains the latest compaction plus entries from `firstKeptEntryId` onward and descendants after the compaction. `buildSessionContext` separately derives the latest thinking level and model from the full active path.
- Session location and bounded discovery (476–659): cwd is resolved and encoded below the agent sessions directory. `loadEntriesFromFile` streams UTF-8 with a 1 MiB buffer, skips malformed records, validates the first parsed record as a session header, and appends a newline when the final record lacked one. Header discovery scans at most 1 MiB, handles a header ending exactly at the limit, and falls back to a full load for oversized headers. `findMostRecentSession` filters JSONL files by valid header and optional resolved cwd, sorts by mtime, and returns null on directory/stat races.
- Session summaries (660–855): asynchronous summary loading streams each file, rejects files without a first session header, tracks latest user-defined name, counts message entries, extracts text from string or text blocks, records the first user message and all user/assistant text, and derives modified time from message timestamps, header timestamp, or stat mtime. Directory listing uses a bounded concurrency of ten, reports progress after each file, ignores one-file failures, and returns newest-first results at the public API boundary.
- `SessionManager` construction and persistence (856–1050): constructor resolves cwd/session directory, creates persistent directories, opens an explicit file or preloaded entries, or creates a new session. Explicit empty files are initialized atomically with a valid header; nonempty invalid files are rejected. New sessions reset indexes/leaf and choose a timestamped JSONL filename. Loading migrates old versions and rebuilds indexes. Persistence defers creation until an assistant message exists, then writes the header and buffered entries once; later entries append. This avoids empty-session artifacts but means user-only turns are not durable until an assistant response.
- Append and metadata operations (1051–1260): append methods create child entries with generated IDs and current timestamps; compaction/branch summaries are forced through dedicated methods. Session names are sanitized to one-line text and resolved from the newest session-info entry. Labels target an existing entry, append a real label node, and maintain a resolved label/timestamp map; clearing a label removes the resolved projection while retaining the append-only record.
- Tree navigation and branching (1261–1505): `getBranch` walks leaf-to-root and returns path order; `getTree` builds defensive nodes, treats self-links/orphans as roots, and iteratively sorts children by timestamp to avoid recursive stack overflow. `branch` moves only the leaf pointer. `branchWithSummary` moves the leaf and appends a summary under the selected parent. `createBranchedSession` copies one path into a new session, removes label nodes while rechaining parents, rewrites compaction references, recreates applicable labels, preserves the source path in `parentSession`, and defers persistence when the resulting path has no assistant message.
- Factory and cross-project operations (1506–1746): `create`, `open`, `continueRecent`, and `inMemory` select persistent/default/custom or memory-backed storage. `open` reads the header first, supports cwd override, and uses a full parse when header scanning is bounded out. `forkFrom` copies non-header entries into a new target-cwd file with a new ID and parent-session pointer. `list` filters custom directories by cwd and `listAll` enumerates all encoded project directories, counts files for accurate progress, loads summaries concurrently, ignores inaccessible directories/files, and sorts by recent activity.

## Errors, cancellation, recovery and side effects

The source is synchronous for mutation and asynchronous for discovery. It writes JSONL directly with `openSync`/`writeFileSync`/`appendFileSync`; there is no fsync or transactional rename around ordinary appends. Corrupt lines are skipped during parsing, while a non-session first parsed record makes a file invalid. Session migration mutates in-memory entries and may rewrite the entire file. Directory and per-file discovery failures are deliberately best-effort and collapse to empty/omitted results. There is no cancellation token for listing; bounded concurrency limits simultaneous summary reads. IDs, parent links, labels, compaction references, and branch paths are the consistency invariants. The source follows symlinked session directories through normal filesystem APIs and does not impose a total byte cap on full session loading.
