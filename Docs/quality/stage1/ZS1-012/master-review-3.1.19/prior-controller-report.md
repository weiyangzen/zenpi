## Complete behavior map

- Imports connect AI request/retry/usage, harness context, session projection and file-operation serialization. `CompactionDetails` persists read/modified lists; `extractFileOperations` carries prior compaction details forward and adds messages. `getMessageFromEntry` projects message/branch-summary/compaction; the compaction-specific wrapper suppresses the prior compaction entry itself to avoid double summary input. The imported utils implementation is context-only, outside this file's acceptance.
- `CompactResult` contains summary, tokens before, optional actual usage, retained message objects and details. `SummaryRequest` is a caller-owned request boundary. Request options force the current abort signal and telemetry, disable cache retention, and choose an explicit or new session ID. `completeSimpleWithRetries` delegates retry policy and callbacks; it does not own journal mutation.
- Settings control enabled, reserve and recent tokens. Defaults are 16384 reserved and 20000 recent. `calculateContextTokens` uses total usage when truthy, otherwise sums input/output/cache fields. Assistant usage is accepted only for non-error/non-aborted replies with positive usage. Entries and message arrays are scanned backwards. Context estimate adds heuristically estimated trailing messages to the most recent usage; with no usage all messages are estimated.
- Heuristic estimation treats image blocks as 4800 characters; text/thinking/tool names and JSON arguments, shell command/output and summary text contribute by role, divided by four and rounded up. JSON serialization failure becomes a literal marker. Unknown role falls through to zero. These are source assumptions, not precise Rust/model token accounting.
- `shouldCompact` compares context usage with window minus reserve only when enabled. `findValidCutPoints` permits user/assistant/custom-like messages and branch summaries, but not tool results or opaque entries. `findTurnStartIndex` walks back to user, bash or branch summary. `findCutPoint` accumulates from the end, chooses the next valid boundary, adjusts preceding non-message entries and reports a split-turn prefix. Thus the source explicitly supports split turns; the Stage 1 whole-turn contract is a deliberate stricter target behavior.
- Summary prompts preserve goals, preferences, progress, blockers, decisions, next actions and critical facts. Update mode incorporates an existing summary. `generateSummaryWithRequest` serializes conversation as data, includes optional prior summary and focus, chooses output up to 80% reserve and model max, and enables reasoning only when supported/requested. It handles aborted/error stop reasons and otherwise returns text and actual usage. Source does not explicitly reject empty or length-terminated summaries here; zenpi's required rejection is an intentional strengthening.
- `prepareCompaction` returns no work for empty history or an immediately preceding compaction. It materializes the prior retained tail as virtual message entries, keeps the previous summary separately, computes current tokens, divides history/prefix/tail, and gathers file operations from all summarized portions. It returns immutable preparation data without persisting it.
- `compactWithRequest` invokes history summary and optional turn-prefix summary sequentially, returns immediately on either error, combines usage, appends formatted file lists and returns retained tail/details. `generateTurnPrefixSummary` uses a separate prefix prompt and up to half the reserve, with the same abort/error handling. Only the host can publish the resulting entry, so request cancellation must prevent host commit.
