# zenpi Execution Blueprint

> **Authoritative checklist.** This is the only mutable requirement and state
> surface for the zenpi execution. Workers never write `[x]`. A worker or the
> controller may move `[ ]` to `[_]` only after a checksum-valid self-tested
> handoff; only the canonical Master may move `[_]` to `[x]` after integration
> and the applicable gates pass. The companion
> `Docs/Zenpi_Execution_Gantt.md` is a read-only projection, never another
> checklist.

```yaml
completion_policy: all required rows [x]; zero [_]; no pending handoff/integration/repair; gates and publish receipt verified
product_modes: tui, headless only
per_item_code_loc_cap: 5000
loc_basis: per-item forecast of implementation/test code LOC attributable to the row (Rust/Python/Shell); docs/config/generated artifacts count 0; declared forecast has a strict upper bound of 5000 (exclusive); aggregate repository LOC is informational
worker_lifecycle: bounded
nested_agents: forbidden
```

## Operating rules

- The Markdown order below is presentation only. `Depends` is the complete
  dependency DAG; duplicate IDs, missing IDs, cycles, and undeclared paths are
  validation failures.
- Every row has a stable ID, layer, owner scope, repository-relative owned
  paths, validators, rollback, and an estimate. A worker may edit only its
  owned paths and its task-local handoff; the canonical checkout is never a
  worker write target.
- Every row also has exactly one `Estimated LOC: N` field. `N` is the forecast
  of implementation/test code LOC attributable to that item (Rust/Python/Shell),
  not a current-file inventory or a project-wide total; `0` is valid for
  documentation, reconciliation, and publication rows. Acceptance requires
  `0 <= N < per_item_code_loc_cap`; estimates are independent and are never
  summed into a project-wide cap.
- Policy correction recorded on 2026-09-03: `per_item_code_loc_cap: 5000`
  applies independently to each row's estimate; it replaces the former
  aggregate Rust source-line interpretation. Aggregate source inventory remains
  telemetry and is not an acceptance limit.
- The Master harvests a checksum-valid `result.json` before pruning a claim,
  applies only the declared patch, reruns gates, reconciles README/spec/Gantt,
  and then changes `[_]` to `[x]`. A failed validation preserves the handoff
  and creates bounded repair work rather than silently accepting it.
- Product scope is deliberately small: one core, one session owner, one
  backend trait, one handoff codec, and exactly two transports (`tui` and
  `headless`). A second UI framework, protocol, server, daemon, broker, or
  hidden mode is out of scope.
- All commits, code comments, task cards, handoffs, and generated execution
  notes are English. The user-facing `README.md` must contain English,
  Simplified Chinese, and Japanese sections.

## Completion checklist

Writing this file is not completion. The objective is complete only when all
required rows are `[x]`, every row carries a strict `Estimated LOC < 5000`
value with durable validation evidence, no `[ ]` or `[_]`/repair/integration
remains, the Gantt projection is current, the binary exposes only `tui` and
`headless`, and the `weiyangzen/zenpi` draft2repo receipt proves the remote
while the local source remains present. Aggregate repository LOC may be
reported for visibility but is not this Blueprint's acceptance cap.
